## Course Redesign — BIT320-S2 (Canvas 3644698) [2026-08-26]

### Overview

BIT320 is a **2-credit, real-world system administration scripting course** that bridges the Windows Admin foundation (BIT221/PRO221) and prepares students for Linux Admin (BIT224) and cloud automation. The course teaches bash, PowerShell, and Python as **equal scripting partners**, with emphasis on selecting the right tool for each automation scenario.

**Key principle:** Technology-agnostic outcomes and comparative analysis, so the course remains relevant as languages evolve.

### Course Learning Outcomes

Upon completion, students will be able to:

1. **Automate server administration workflows using scripting languages**
2. **Process system data to extract insights and generate reports**
3. **Evaluate and select appropriate scripting approaches based on context and requirements**
4. **Implement automation scripts with basic error handling, scheduling integration, and attention to code quality**

### Course Structure

**Duration:** 5 weeks  
**Contact Hours:** 20 (4 hours/week)  
**Homework:** ~40 hours (~8 hours/week)  
**Total:** 60 hours (appropriate for 2-credit course)

**Scripting Languages:** Bash, PowerShell, Python (equal emphasis; students build competence in all three)

**Pedagogical Approach:**
- **Primary labs:** Full assignment in the language where it's strongest for the task
- **Comparative analysis:** Optional/bonus labs showing how other languages solve the same problem
- **Reflection:** Students analyze trade-offs: speed, readability, portability, maintainability, team expertise

### Weekly Lab Breakdown

#### Week 1: Bash Fundamentals & Log Analysis (4 hrs contact, 10 hrs homework)

**Contact:** Bash basics, text processing tools (grep, awk, sed), log analysis concepts, introducing crisis scenario

**UNIFIED SCENARIO (Weeks 1-4):** PaymentService Crisis Investigation
- **Context:** On September 1st at 8:15 AM, PaymentService experienced connection timeouts that cascaded through the afternoon. Customers couldn't complete transactions. Infrastructure team needs you to extract insights from the application log.
- **Same log file across all three weeks (system.txt):** 1000-entry log spanning ~36 hours with realistic mix of INFO/WARNING/ERROR messages from 8 services
- **Same analysis tasks across Weeks 1-3:** Answer five critical questions: (1) How many failures? (2) Which services affected? (3) Most common errors? (4) Timeline? (5) Root cause hypothesis?
- **Different language implementations reveal different strengths:** Bash (speed), PowerShell (clarity), Python (maintainability)

**Lab 1.1 (25 pts, 1 hr):** "Infrastructure Setup — Environment Verification"
- **Scenario:** Install/verify bash, PowerShell, and Python; confirm all three environments work
- **Deliverable:** Screenshots of version checks and test commands
- **Outcome addressed:** #1 (infrastructure foundation)

**Lab 1.2 (25 pts, 1.5 hrs):** "System Command Execution & Output Processing"
- **Scenario:** Execute system information scripts in all three languages; gather real data proving environments work
- **Implementation:** Bash (system commands), PowerShell (Get-* cmdlets), Python (subprocess)
- **Deliverable:** Scripts + screenshots showing output from each language
- **Outcome addressed:** #1 (automate), #2 (process data)

**Lab 1.3 (100 pts, 5-6 hrs):** "Log Analysis - Bash Deep Dive"
- **Scenario:** Investigate the PaymentService crisis using bash text pipelines (THIS WEEK: bash approach)
- **Implementation:** Pure bash using grep, awk, sed, sort, uniq to extract insights from system.txt
- **Tasks:** Answer five critical questions about the crisis (scope, affected services, failure modes, timeline, root cause hypothesis)
- **Deliverable:** Bash script, output files, performance metrics, screenshots, 200-300 word hypothesis backed by evidence
- **Focus:** Demonstrate bash's native strength (speed, efficiency) and text-pipeline paradigm; emphasize that pipeline chains reveal data pattern efficiently
- **Critical thinking:** Students must interpret data and form hypotheses, not just run commands
- **Outcome addressed:** #1 (automate), #2 (process data), #3 (understand bash paradigm)

#### Week 2: PowerShell Fundamentals & Object Pipelines (4 hrs contact, 10 hrs homework)

**Contact:** PowerShell basics, object pipelines, cmdlet patterns, comparing paradigms

**Lab 2.1 (100 pts, 5-6 hrs): "Log Analysis - PowerShell"**
- **Scenario:** Investigate the same PaymentService crisis using PowerShell object pipelines (THIS WEEK: PowerShell approach)
- **Implementation:** Pure PowerShell using Get-Content, Where-Object, Group-Object, Select-Object to parse and analyze same system.txt
- **Tasks:** Answer the same five critical questions as Week 1 (scope, affected services, failure modes, timeline, root cause hypothesis)
- **Deliverable:** PowerShell script, output files, performance metrics, 200-300 word hypothesis, comparison reflection (50-100 words)
- **Focus:** Demonstrate PowerShell's object-based paradigm—convert raw text into objects with properties, then filter/aggregate using object-based operations
- **Critical thinking:** Students see how PowerShell's approach (object filtering) differs from bash's (text pipelines), notice results are identical, reflect on which felt more natural
- **Comparison reflection:** Students compare their PowerShell analysis to Week 1 bash results—was PowerShell easier/harder to write? Which paradigm was clearer?
- **Outcome addressed:** #1 (automate), #2 (process data), #3 (understand PowerShell paradigm, compare to bash)

#### Week 3: Python Fundamentals & Readable Logic (4 hrs contact, 10 hrs homework)

**Contact:** Python basics, file I/O, data structures, error handling intro, paradigm comparison

**Lab 3.1 (100 pts, 5-6 hrs): "Log Analysis - Python"**
- **Scenario:** Investigate the same PaymentService crisis using Python (THIS WEEK: Python approach)
- **Implementation:** Pure Python using file I/O, data structures (dictionaries, Counter, lists), explicit logic to parse and analyze same system.txt
- **Tasks:** Answer the same five critical questions as Weeks 1-2 (scope, affected services, failure modes, timeline, root cause hypothesis)
- **Deliverable:** Python script, output files, performance metrics, 200-300 word hypothesis, language reflection (150-200 words)
- **Focus:** Demonstrate Python's strength—express business logic explicitly and clearly, making analysis maintainable and extensible
- **Critical thinking:** Students see how Python's explicit data structures and readable code compare to bash (cryptic but fast) and PowerShell (objects but verbose)
- **Language reflection:** Students reflect on which language was easiest to modify, which would be best if they needed to add new analysis, which they'd choose to maintain in production
- **Outcome addressed:** #1 (automate), #2 (process data), #3 (understand Python paradigm and compare across all three languages)

#### Week 4: Tool Selection & Comparative Analysis (4 hrs contact, 8-10 hrs homework)

**Contact:** Tool selection frameworks, comparative evaluation, decision-making, paradigm trade-offs

**Lab 4.1 (100 pts, 8-10 hrs): "Tool Selection & Comparative Analysis"**
- **Scenario:** You've now solved the PaymentService crisis in three languages. Each was correct. Each revealed different strengths. Now: become a tool strategist.
- **Analyze your three implementations** (bash, PowerShell, Python scripts from Labs 1.3, 2.1, 3.1)—NO new coding required
- **Systematic evaluation** across seven dimensions:
  1. Execution speed (how fast did each complete the analysis?)
  2. Code clarity (if someone else opened your script, which would be easiest to understand?)
  3. Maintainability (if requirements changed, which would be easiest to modify?)
  4. Extensibility (if you needed to add new analysis, which would require least rework?)
  5. Platform suitability (Linux, Windows, cross-platform considerations)
  6. Learning curve (how long did it take to write each? Which paradigm felt natural?)
  7. Deployment complexity (what does each require to run in production?)
- **Deliverables:**
  - Dimension Comparison Table: 7 dimensions × 3 languages, with scores (1-5) and justifications
  - Real-World Scenarios (3 distinct scenarios): 
    - Quick investigation under time pressure → which language? Why?
    - Ongoing monitoring over 2 years → which language? Why?
    - Complex analysis with charts and statistical work → which language? Why?
  - Your recommendation for the PaymentService crisis (300-400 words): which language would you choose in production and why? Show trade-off thinking.
- **Focus:** Understand that there's no single "best" language—you choose bash for speed, PowerShell for Windows, Python for maintenance. Context drives decisions.
- **Critical thinking:** Defend your choices with evidence. Recognize trade-offs: "I'd choose Python for clarity, but accept that it's slower than bash."
- **Outcome addressed:** #3 (evaluate and select appropriate approaches based on context, constraints, and trade-offs)

#### Week 5: Performance Monitoring Capstone (4 hrs contact, 10-12 hrs homework)

**Contact:** Capstone project overview, tool selection strategy, production patterns

**Lab 5.1 (100 pts, 10 hrs): "Windows Event Log Analysis — Capstone Project"**
- **Scenario:** Your Windows 11 laptop has been logging system, security, and application events since it was first started. Extract and analyze these logs to answer real operational questions about system health, security, and reliability.
- **Data source:** Windows Event Logs (already on their laptop; no collection period needed)
- **Investigation objectives:** Answer five concrete questions about their system:
  1. What is the most common event type in the past 7 days? (System, Security, Application)
  2. How many errors vs. warnings vs. information entries exist?
  3. Which components/sources generate the most events? (e.g., Service Control Manager, Kernel-General)
  4. Are there patterns in error timing? (e.g., all errors at startup, or spread throughout the day?)
  5. What does the error distribution tell you about system stability?
- **Language selection:** Choose bash, PowerShell, Python, or a hybrid approach based on what you learned in Weeks 1-4
- **Implementation:**
  - Extract Windows Event Logs to CSV (provided PowerShell script)
  - Parse and analyze the CSV in your chosen language
  - Answer all five investigation questions with supporting data/charts
  - Justify your language choice based on the analysis you performed
- **Deliverables:**
  - Raw event log data (CSV export, provided)
  - Analysis script in your chosen language(s)
  - Report (500 - 750 words) answering all five questions with evidence
  - Tool selection reflection (250 - 350 words): why did you choose this language? What would you choose for a different scenario?
- **Focus:** Integrate all five weeks: bash text processing (grep, awk, sed), PowerShell objects (Get-WinEvent, filtering), Python logic (Counter, dictionaries), tool selection thinking (when to use which language)
- **Outcome addressed:** #1-4 (all learning outcomes, with emphasis on #3 - tool selection for real-world automation)

### Unified Scenario Design (2026-09-10)

**Major Pedagogical Enhancement:** Weeks 1-4 unified around the **PaymentService Crisis Investigation** scenario.

**Design Rationale:**
- **Same log file, different phases across Weeks 1-3** (system.log, 1000 entries, ~36 hours total):
  - Week 1 (Bash): Analyze crisis ONSET phase (first 12 hours, ~300 entries) — understand how crisis started
  - Week 2 (PowerShell): Analyze peak/CASCADE phase (middle 12 hours, ~350 entries) — understand how crisis spread
  - Week 3 (Python): Analyze RECOVERY phase (final 12 hours, ~300 entries) — understand resolution and lingering issues
- **Same five critical questions** applied to each phase: Scope, affected services, failure modes, timeline, root cause hypothesis
- **Phase-based design prevents shortcutting**: Students must analyze genuinely different data subsets, not copy-paste results
- **Crisis arc narrative**: Onset → Cascade → Recovery tells a coherent story; students compare phases to understand full mechanism
- **Different implementations reveal language strengths**: 
  - Week 1 (Bash): Speed, efficiency, native text-processing power for onset analysis
  - Week 2 (PowerShell): Clarity through objects reveals cascade patterns that text pipelines obscure
  - Week 3 (Python): Explicit logic enables integrated analysis across all three phases
- **Week 4 (Comparative Analysis)**: Systematically evaluate all three across 7 dimensions, make justified tool-selection decisions for real-world scenarios
- **High engagement**: Students are "investigating a real crisis," not just "analyzing log data"
- **Critical thinking**: Students must interpret data and form hypotheses backed by evidence, not just run commands
- **Paradigm comparison**: Students see that bash/PowerShell/Python produce identical results but through fundamentally different approaches—revealing when each excels
