## Course Redesign — BIT320-S2 (Canvas 3644698) [2026-08-26]

### Overview

BIT320 is a **2-credit, real-world system administration scripting course** that bridges the Windows Admin foundation (BIT221/PRO221) and prepares students for Linux Admin (BIT224) and cloud automation. The course teaches bash, PowerShell, and Python as **equal scripting partners**, with emphasis on selecting the right tool for each automation scenario.

**Key principle:** Technology-agnostic outcomes and comparative analysis, so the course remains relevant as languages evolve.

### Course Learning Outcomes

Upon completion, students will be able to:

1. **Automate server administration workflows using scripting languages**
2. **Process system data to extract insights and generate reports**
3. **Evaluate and select appropriate scripting approaches based on context and requirements**
4. **Implement automation scripts with basic error handling, scheduling integration, and attention to code quality**

### Course Structure

**Duration:** 5 weeks  
**Contact Hours:** 20 (4 hours/week)  
**Homework:** ~40 hours (~8 hours/week)  
**Total:** 60 hours (appropriate for 2-credit course)

**Scripting Languages:** Bash, PowerShell, Python (equal emphasis; students build competence in all three)

**Pedagogical Approach:**
- **Primary labs:** Full assignment in the language where it's strongest for the task
- **Comparative analysis:** Optional/bonus labs showing how other languages solve the same problem
- **Reflection:** Students analyze trade-offs: speed, readability, portability, maintainability, team expertise

### Weekly Lab Breakdown

#### Week 1: Bash Fundamentals & Log Analysis (4 hrs contact, 10 hrs homework)

**Contact:** Bash basics, text processing tools (grep, awk, sed), log analysis concepts

**Lab 1.1 (25 pts, 1 hr):** "Infrastructure Setup — Environment Verification"
- **Scenario:** Install/verify bash, PowerShell, and Python; confirm all three environments work
- **Deliverable:** Screenshots of version checks and test commands
- **Outcome addressed:** #1 (infrastructure foundation)

**Lab 1.2 (25 pts, 1.5 hrs):** "System Command Execution & Output Processing"
- **Scenario:** Execute system information scripts in all three languages; gather real data proving environments work
- **Implementation:** Bash (system commands), PowerShell (Get-* cmdlets), Python (subprocess)
- **Deliverable:** Scripts + screenshots showing output from each language
- **Outcome addressed:** #1 (automate), #2 (process data)

**Lab 1.3 (100 pts, 5-6 hrs):** "Log Analysis - Bash Deep Dive"
- **Scenario:** Analyze a sample application log file (provided: sample_log.txt) using bash text pipelines
- **Implementation:** Pure bash using grep, awk, sed, sort, uniq
- **Tasks:** Count errors by component, identify top 10 error messages, extract timeline, generate formatted report
- **Deliverable:** Bash script, output files, performance metrics, screenshots showing successful execution
- **Focus:** Demonstrate bash's native strength in text processing and streaming efficiency
- **Outcome addressed:** #1 (automate), #2 (process data), #3 (understand bash paradigm)

#### Week 2: PowerShell Fundamentals & Object Pipelines (4 hrs contact, 10 hrs homework)

**Contact:** PowerShell basics, object pipelines, cmdlet patterns

**Lab 2.1 (100 pts, 5-6 hrs): "Log Analysis - PowerShell"**
- **Scenario:** Analyze the same log file from Lab 1.3 using PowerShell object pipelines
- **Implementation:** Pure PowerShell using Get-Content, Where-Object, Group-Object, Select-Object
- **Tasks:** Count errors by component, identify top 10 error messages, extract timeline, generate formatted report (matching Lab 1.3 output format)
- **Deliverable:** PowerShell script, output files, performance metrics, reflection on paradigm differences from bash
- **Focus:** Demonstrate PowerShell's object-based approach and how it differs fundamentally from bash text pipelines
- **Comparison:** Students reflect on how PowerShell's approach to the same problem differs from bash, and when you'd choose each
- **Outcome addressed:** #1 (automate), #2 (process data), #3 (understand PowerShell paradigm)

#### Week 3: Python Fundamentals & Readable Logic (4 hrs contact, 10 hrs homework)

**Contact:** Python basics, file I/O, data structures, error handling intro

**Lab 3.1 (100 pts, 5-6 hrs): "Log Analysis - Python"**
- **Scenario:** Analyze the same log file from Labs 1.3 and 2.1 using Python
- **Implementation:** Pure Python using file I/O, dictionaries, lists, regex
- **Tasks:** Count errors by component, identify top 10 error messages, extract timeline, generate formatted report (matching Labs 1.3 and 2.1 output format)
- **Deliverable:** Python script, output files, performance metrics, comprehensive comparative analysis
- **Focus:** Demonstrate Python's explicit, readable logic and how it contrasts with bash text pipelines and PowerShell object filtering
- **Analysis:** Students analyze all three implementations side-by-side, discussing when each language excels and when you'd choose it
- **Outcome addressed:** #1 (automate), #2 (process data), #3 (understand Python paradigm)

#### Week 4: Tool Selection & Comparative Analysis (4 hrs contact, 8-10 hrs homework)

**Contact:** Tool selection frameworks, comparative evaluation, decision-making

**Lab 4.1 (100 pts, 8-10 hrs): "Tool Selection & Comparative Analysis"**
- **Scenario:** Analyze your three log analysis implementations (bash, PowerShell, Python) and create a comprehensive comparative report
- **No new coding required:** Use the three scripts you already built in Labs 1.3, 2.1, and 3.1
- **Analysis:** Compare across seven dimensions:
  - Development time
  - Runtime performance (measure in seconds)
  - Memory usage (estimate or measure)
  - Maintainability (readability, ease of modification)
  - Scalability (can it handle 10x larger files?)
  - Error handling (robustness and recovery)
  - Deployment/platform (where does it run, what dependencies?)
- **Deliverables:** 
  - Comparative table with metrics across all seven dimensions
  - Decision framework essay (300-400 words): when to choose bash vs PowerShell vs Python
  - Real-world scenario analysis: given 4 different automation scenarios, justify which language you'd choose
- **Focus:** Develop systematic tool selection thinking based on constraints and requirements
- **Outcome addressed:** #3 (evaluate and select appropriate approaches)

#### Week 5: Performance Monitoring Capstone (4 hrs contact, 10-12 hrs homework)

**Contact:** Capstone project overview, tool selection strategy, production patterns

**Lab 5.1 (100 pts, 10 hrs): "Performance Baseline & Trending — Capstone Project"**
- **Scenario:** Build a performance monitoring solution that collects system metrics over 24-48 hours and analyzes trends to answer capacity planning questions
- **Language selection:** Choose bash, PowerShell, Python, or a hybrid approach based on what you learned in Weeks 1-4
- **Implementation:**
  - Data collection (passive; runs in background over 24-48 hours)
  - Trend analysis (active; identify growth patterns, anomalies, capacity risks)
  - Capacity projection (when will you run out of disk/memory?)
  - Visualizations (charts, graphs showing trends)
- **Deliverables:**
  - Collection script(s) in your chosen language(s)
  - Raw data files (CSV format)
  - Analysis report with findings and recommendations
  - Tool selection justification document explaining why you chose your language(s)
- **Focus:** Integrate all five weeks: bash text processing, PowerShell objects, Python logic, comparative thinking, production patterns
- **Outcome addressed:** #1-4 (all learning outcomes, with emphasis on #3 - tool selection for real-world automation)
