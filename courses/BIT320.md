## Course Redesign — BIT320-S2 (Canvas 3644698) [2026-08-26]

### Overview

BIT320 is a **2-credit, real-world system administration scripting course** that bridges the Windows Admin foundation (BIT221/PRO221) and prepares students for Linux Admin (BIT224) and cloud automation. The course teaches bash, PowerShell, and Python as **equal scripting partners**, with emphasis on selecting the right tool for each automation scenario.

**Key principle:** Technology-agnostic outcomes and comparative analysis, so the course remains relevant as languages evolve.

### Course Learning Outcomes

Upon completion, students will be able to:

1. **Automate server administration workflows using scripting languages**
2. **Process system data to extract insights and generate reports**
3. **Evaluate and select appropriate scripting approaches based on context and requirements**
4. **Implement automation scripts with basic error handling, scheduling integration, and attention to code quality**

### Course Structure

**Duration:** 5 weeks  
**Contact Hours:** 20 (4 hours/week)  
**Homework:** ~40 hours (~8 hours/week)  
**Total:** 60 hours (appropriate for 2-credit course)

**Scripting Languages:** Bash, PowerShell, Python (equal emphasis; students build competence in all three)

**Pedagogical Approach:**
- **Primary labs:** Full assignment in the language where it's strongest for the task
- **Comparative analysis:** Optional/bonus labs showing how other languages solve the same problem
- **Reflection:** Students analyze trade-offs: speed, readability, portability, maintainability, team expertise

### Weekly Lab Breakdown

#### Week 1: Environment Setup & Comparative Log Analysis (4 hrs contact, 8 hrs homework)

**Contact:** Setup all three environments, demonstrate log parsing approaches, guided comparative analysis

**Lab 1.1 (25 pts, 1 hr):** "Infrastructure Setup — Environment Verification"
- **Scenario:** Install/verify bash, PowerShell, and Python; confirm all three environments work
- **Deliverable:** Screenshots of version checks and test commands
- **Outcome addressed:** #1 (infrastructure foundation)

**Lab 1.2 (25 pts, 1.5 hrs):** "System Command Execution & Output Processing"
- **Scenario:** Execute system information scripts in all three languages; gather real data proving environments work
- **Implementation:** Bash (system commands), PowerShell (Get-* cmdlets), Python (subprocess)
- **Deliverable:** Scripts + screenshots showing output from each language
- **Outcome addressed:** #1 (automate), #2 (process data)

**Lab 1.3 (100 pts, 5.5 hrs):** "Log Analysis Starter — Comparative Language Approaches"
- **Scenario:** Analyze a sample application log file (provided: sample_log.txt); extract key metrics (error count, top error types, timeline) and generate summary report
- **Implementation:** All three languages (bash, PowerShell, Python) — students experience each paradigm
  - **Bash:** `grep`, `awk`, `sort`, `uniq` — text pipelines (demonstrates bash' native strength)
  - **PowerShell:** `Select-Object`, `Where-Object`, `Group-Object` — object-based filtering (shows PowerShell advantage)
  - **Python:** Regex, file I/O, dictionaries — readable logic for complex parsing (demonstrates Python readability)
- **Deliverable:** Scripts, output files/screenshots, comparison table (lines of code, readability, execution time, paradigm fit, ease of understanding)
- **Reflection:** 
  - Which language felt most natural to you?
  - Which was fastest to write? Most readable?
  - For a one-off analysis, which would you use? Why?
  - If this became a daily job, which would you choose? Why?
- **Scaffolds:** Foreshadows Week 3 PowerShell focus (students will see how each language approaches the same data)
- **Outcome addressed:** #1 (automate), #2 (process data), #3 (compare approaches)

#### Week 2: Bash Fundamentals & Text Processing (4 hrs contact, 6 hrs homework)

**Contact:** Variables, control flow, text processing paradigms (grep, awk, sort, uniq)

**Lab 2.1 (50 pts, 4-5 hrs): "Log Summary Script — Bash Fundamentals & Text Processing"**
- **Scenario:** Parse application log file; summarize error counts by type and severity
- **Primary language:** Bash (emphasizing text pipeline strength)
- **Implementation:** Use bash text tools (grep, awk, sort, uniq) to demonstrate bash' native strength
- **Bonus (optional):** Show same script in PowerShell (object-based) and Python (readable logic); compare approaches
- **Outcome addressed:** #1 (automate), #2 (process data), #3 (tool selection - bash for text)

#### Week 3: PowerShell Object Pipelines & Windows Analysis (4 hrs contact, 7 hrs homework)

**Contact:** Object-based filtering paradigms, Get-EventLog, Where-Object, Group-Object

**Lab 3.1 (100 pts, 6-7 hrs): "Windows Event Log Audit — PowerShell Object Pipeline Analysis"**
- **Scenario:** Analyze Windows Event Log for failed authentication attempts; identify patterns and suspicious activity; generate security audit report
- **Primary language:** PowerShell (object-based filtering is PowerShell's strength; uses Get-EventLog, Where-Object, Group-Object, Select-Object)
- **Why PowerShell:** This task demonstrates PowerShell's native advantage for Windows infrastructure analysis — object pipelines beat text parsing for structured data
- **Bonus comparison (optional):** Same analysis in bash (grep/awk) and Python (regex); document why PowerShell wins for this task
- **Deliverable:** PowerShell script, security audit report, test evidence, optional comparative analysis
- **Outcome addressed:** #1 (automate), #2 (process data), #3 (tool selection - PowerShell for Windows objects)

#### Week 4: Python Fundamentals & Production Automation (4 hrs contact, 8 hrs homework)

**Contact:** Error handling patterns (try/except), scheduling mechanisms, production-ready code patterns

**Lab 4.1 (50 pts, 3-4 hrs): "Service Monitoring in Python — Error Handling & Production Patterns"**
- **Scenario:** Monitor critical services on Hyper-V Windows Server VMs; automatically restart if failed; log all actions with timestamps
- **Primary language:** Python (emphasizing structured error handling and logging)
- **Skills:** Query service status, try/except blocks, structured logging, graceful error recovery
- **Why Python:** Demonstrates Python's strength for readable error handling and cross-platform automation
- **Foundation for:** Lab 4.2 (add scheduling) and Lab 4.3 (add alerting and cross-platform)
- **Outcome addressed:** #1 (automate), #4 (error handling, production patterns)

**Lab 4.2 (25 pts, 1-2 hrs): "Scheduled Automation — Integrate Your Monitoring Script with Task Scheduling"**
- **Extend Lab 4.1:** Integrate with cron (Linux) or Task Scheduler (Windows); schedule to run every 5 minutes
- **Skills:** Job scheduling, unattended execution, log integration
- **Why this:** Bridge between "I wrote a script" and "I deployed automation"
- **Outcome addressed:** #4 (production integration)

**Lab 4.3 (50 pts, 3-4 hrs): "Production Hardening — Error Alerting & Windows Integration"**
- **Extend Lab 4.1+4.2:** Add escalating alerts (email/Slack on repeated failures), retry logic with exponential backoff, cross-platform monitoring (Windows + Linux)
- **Skills:** Advanced error recovery, alerting mechanisms, cross-platform orchestration
- **Why this:** Teaches production-grade patterns students will see in real infrastructure
- **Outcome addressed:** #1 (integrate platforms), #4 (production-ready code)

#### Week 5: Performance Baseline & Trending — Comparative Analysis Capstone (4 hrs contact, 10 hrs homework)

**Contact:** Capstone overview, tool selection for data collection vs. analysis, guidance on comparative analysis

**Lab 5.1 (100 pts, 8 hrs lab + 2 hrs reflection): "Performance Baseline & Trending — Comparative Analysis Capstone"**
- **Scenario:** Build a performance baseline and trending solution: collect system metrics (CPU, memory, disk, network) over time and analyze trends to answer capacity planning questions
- **Language selection:** Choose which language(s) make sense for collection, aggregation, and analysis (bash, PowerShell, Python, or combination)
- **Implementation:** Data collection (24-48 hours), trend analysis, capacity risk identification, visualizations
- **Comparative analysis:** Document tool selection trade-offs for each component; show code examples of how each language would solve collection and analysis
- **Why this:** Brings together all five weeks; demonstrates real-world tool selection thinking
- **Deliverable:** Scripts, data files, analysis report with visualizations, tool selection documentation, comparative code examples
- **Outcome addressed:** #1-4 (all integrated, with emphasis on #3 - tool selection)
