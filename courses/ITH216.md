  - Covers: Path attributes and decision process (Weight > Local Preference > AS Path > MED > eBGP/iBGP > IGP cost)
  - Weight (0-65535, local router): Highest priority. Local routes have weight 32768, received routes weight 0
  - Local Preference (0-4294967295, default 100): AS-wide preference. ISP1 routes local-pref 200 > ISP2 local-pref 150 (all routers prefer ISP1)
  - MED (Multi-Exit Discriminator): Sent to eBGP neighbor to indicate preferred entry path. "Use this exit to reach our AS"
  - AS Path Length: Shorter preferred. AS-path prepending adds fake ASes to make path appear longer (prevents external use of internal paths)
  - Route filtering: Prefix lists and route-maps for inbound/outbound filtering. Deny unwanted prefixes; set attributes on accepted routes
  - Configuration examples: Prefix list filtering ISP routes to specific prefixes, route-map with local-preference adjustment, AS-path prepending for loop prevention
  - Route aggregation (summary-only): Combines 10.1.0.0/24, 10.1.1.0/24, 10.1.2.0/24 into 10.1.0.0/22. Reduces table size and convergence time
  - BGP redistribution: Import EIGRP routes into BGP with route-map filtering. Set AS-path prepend to prevent external use as backup
  - Verification commands: show bgp ipv4 unicast X.X.X.X/XX (path attributes detail), show bgp ipv4 unicast neighbors 192.168.1.1 received-routes (all received prefixes)
  - Troubleshooting: Convergence slow (use BFD or reduced timers), received route filtering not working (check prefix-list and route-map syntax)
  - Real-world scenarios: Multi-ISP redundancy (primary with higher local-pref, backup with lower), BGP on a stick (multiple VLANs with different policies), large campus networks with iBGP backbone and route reflectors
