## 2. Relevance to current DevOps practice

The arc is sound. The tooling is about five years behind current practice. Gaps, in priority order:

1. **Kubernetes / orchestration.** Named once in the outline. Docker alone is no longer most DevOps roles' daily work. Highest-value addition.
2. **Terraform and cloud provisioning.** Ansible covers configuration only. No provisioning, no cloud, which PLO4 needs.
3. **Hosted CI (GitHub Actions).** Jenkins is still in use, but most new pipelines are hosted. Teach the hosted workflow alongside Jenkins.
4. **Secrets and supply-chain security.** Image scanning, signing, SBOMs, and secrets in pipelines. Overlaps PLO3.
5. **Observability beyond Zabbix.** Zabbix is a legitimate on-prem example. Teach metrics, logs and traces as concepts; Prometheus and Grafana as the cloud-native equivalent.
6. **SRE practice.** SLOs, error budgets, incident response. Students should run a blameless post-mortem, not only read about one.
7. **AI in operations.** AI appears only in the final essay. Make the outline's optional AI-drafts-a-Dockerfile demo a graded lab with verification.

Kept: Git, Ansible, Docker, Zabbix and the SDLC comparison.

## 4. Implementation: Kubernetes, cloud provisioning, GitHub Actions (no budget)

All three run on the two-VM setup plus free GitHub accounts. Nothing here requires a paid service.

### Kubernetes: k3s on the Ubuntu Server VM
- Install k3s (single-node Kubernetes) on the Ubuntu Server VM, which already runs Docker. Pin the version. Use the official install script.
- Do **not** run it on the Mint VM. Mint is the control node and runs Jenkins and Ansible.
- Lab (M6): deploy the nginx image from Docker Web Server as a Deployment and Service; scale it; do a rolling update; delete a pod to show self-healing; write the manifest in YAML (ties to the YAML lab).
- Build the k3s lab against the Ubuntu VM's RAM budget (see section 5). The Systems Setup assignment says 1 GB minimum for Ubuntu; this lab needs about 4 GB. Update the Systems Setup text.

### Cloud provisioning: Terraform against the local Docker daemon (M7)
- Terraform's Docker provider (`kreuzwerker/docker`) creates networks, volumes and containers on the Ubuntu VM's Docker daemon, reached from Mint over SSH (`DOCKER_HOST=ssh://...`). This teaches declarative provisioning, `plan`/`apply`, and state, the core of the cloud lesson, with no account.
- For real cloud APIs: use free tiers under an instructor-controlled account, or a local AWS API emulator. Verify current licensing and sign-up requirements before committing to either. Student cloud accounts raise data-handling questions, so keep any cloud work optional or instructor-held.
- The PLO4 decision memo uses the Terraform lab as evidence.

### GitHub Actions: hosted workflow plus self-hosted runner (M5)
- Hosted runners on the free GitHub plan cover workflow syntax: triggers, jobs, steps, secrets, artifacts. Run build, lint and test there. Verify current free-plan minute limits before the course starts.
- For deployment to the Ubuntu VM, register a self-hosted runner on the Mint VM. The runner makes outbound connections only, so it works through campus networks without port forwarding. The deploy step updates the target with Ansible or Docker.
- Store SSH keys and tokens in GitHub secrets, never in the repo. Doubles as a PLO3 lesson.

## 5. Constraints and risks

- **RAM is the binding constraint.** Estimated per-laptop load: Mint 4 GB, Ubuntu 4 GB with k3s, Zabbix appliance 2 GB or more, plus host OS overhead. Roughly 10 GB free for the VMs. These are estimates; test on a clean build before publishing.
  - State a **16 GB laptop minimum** on the Systems Setup page.
  - Low-RAM fallback: run one VM at a time, use snapshots to switch, and skip the k3s and Zabbix appliance steps if needed (mark them as the fallback path in the lab text).
- **Bridged networking may be blocked** on campus Wi-Fi. Use NAT Network with port forwarding as the fallback. Keep the self-hosted runner outbound-only.
- **Snapshot discipline.** Labs assume clean snapshots (Systems Setup). Add a snapshot step before the k3s and Terraform labs.
- **Placement.** Kubernetes fits the Docker week (M6). Terraform and the cloud decision fit M7. GitHub Actions is a comparison in the Jenkins week (M5), not a replacement.
